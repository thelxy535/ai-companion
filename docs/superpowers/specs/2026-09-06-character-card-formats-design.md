# 角色资料卡多格式设计

## 目标

让自定义角色可以在弦曜与其他角色卡工具之间迁移，同时提供一个不会丢失弦曜专有配置的完整格式，并支持适合人工阅读和分享的 Markdown/TXT 导出。

## 格式范围

### 导入

- Character Card V2/V3 JSON：继续支持标准 `data` envelope、裸 data 对象和常见 V2/V3 字段。
- 弦曜完整 JSON：通过 `format = sylora_character` 标识，保存完整 `CustomCharacter` 配置。
- Markdown/TXT：按标题和标签解析名称、描述、背景、场景、开场白、示例对话与标签；无法识别的内容保留到描述或创作者备注。

### 导出

- 标准 JSON：用于跨工具分享，保持当前 V2 结构。
- 弦曜完整 JSON：使用 `.sylora.json` 文件名，保留人格、行为、语音、Character Book 和元数据。
- Markdown：适合阅读、发布和手动编辑。
- TXT：提供无 Markdown 依赖的纯文本版本。

## 兼容与安全

- 旧 V2/V3 JSON 的导入行为不改变。
- 导入文件仍限制为 2 MiB；所有解析失败都返回可读错误，不写入数据库。
- 外部格式缺少的字段使用现有默认值，不凭空覆盖用户设置。
- API key、用户数据库、聊天记录和本地设置不进入任何角色导出格式。

## UI 与数据流

- 导出动作先生成文件名与内容，再由系统文件选择器保存。
- 导入文件选择器允许 JSON、Markdown 和文本类型；解析器根据内容自动识别格式。
- 导出格式选择放在角色列表的导出菜单中，保持现有导入确认流程。
- 角色卡映射层负责外部格式与 `CustomCharacter` 的双向转换，UI 不直接拼接角色字段。

## 测试

- V2/V3、裸 data、弦曜完整 JSON 的 round-trip 测试。
- Markdown/TXT 的关键字段解析和缺失字段默认值测试。
- 导出内容不包含密钥、数据库字段和聊天历史。
- 运行角色卡单元测试与 `assembleDebug`。
