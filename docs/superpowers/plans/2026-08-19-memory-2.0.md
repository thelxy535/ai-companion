# Memory 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Upgrade CC-Switch from message-based memory to a local-first, auditable, recoverable memory system without breaking existing chat history.

**Architecture:** Keep `MessageEntity`, the existing legacy `memories` table, and vector storage compatible. Add immutable source records, review proposals, formal memory nodes, evidence, versions, relations, retrieval traces, and feedback as separate Room entities. All model-generated changes enter proposal tables and become formal state only through explicit repository commands.

**Tech Stack:** Kotlin, Jetpack Room, Hilt, Coroutines/Flow, Jetpack Compose, existing repository/ViewModel patterns, JUnit.

## Global Constraints

- Original messages and source snapshots are immutable.
- AI-generated candidates never enter formal memory or chat retrieval before user approval.
- Every formal memory is scoped to a companion/role or explicit shared scope.
- User edits append versions; soft deletion and restore are required.
- Existing chat history, legacy memory, vector memory, import, and export remain usable after every task.
- Every database write crossing more than one new table uses a Room transaction.
- Do not modify unrelated dirty-worktree files.
